# 法律形式化元模型与精确语义规约

> 项目：经济法知识图谱与上市公司治理合规推理系统  
> 文档定位：形式化层最高约束规范  
> 目标：给对象、关系、事件、规则、时间、证据与证明定义唯一、可计算、可校验的语义。

---

# 1. 规约目标

本规约用于回答：

1. 法律对象如何唯一分类；
2. 关系的定义域、值域、基数和时间语义如何确定；
3. “董事参加会议”“公司拥有董事会”等表达如何消除歧义；
4. 业务事件如何改变事实状态；
5. 义务、禁止、允许、授权分别意味着什么；
6. 未知、冲突和不适用如何区分；
7. 规则冲突、例外和新旧规则如何处理；
8. 法律结论如何从事实、规则和证据中形式推出。

系统定义为：

\[
\mathcal{L}=(\mathcal{T},\mathcal{O},\mathcal{R},\mathcal{I},\mathcal{E},\mathcal{N},\mathcal{V},\mathcal{P},\mathcal{Q})
\]

| 符号 | 含义 |
|---|---|
| \(\mathcal{T}\) | 类型系统 |
| \(\mathcal{O}\) | 对象实例集合 |
| \(\mathcal{R}\) | 关系与属性签名 |
| \(\mathcal{I}\) | 不变量集合 |
| \(\mathcal{E}\) | 事件与状态变换 |
| \(\mathcal{N}\) | 法律规范集合 |
| \(\mathcal{V}\) | 真值与知识状态 |
| \(\mathcal{P}\) | 规则优先级与冲突处理 |
| \(\mathcal{Q}\) | 证明与可追溯结构 |

# 2. 基本语义原则

## 2.1 对象与角色分离

自然人不是董事。自然人只是在一定时间内承担董事角色。

错误：

\[
Zhang=Director
\]

正确：

\[
Person(Zhang)
\]

\[
RoleAssignment(RA_1)
\]

\[
Holder(RA_1,Zhang)
\]

\[
RoleType(RA_1,DirectorRole)
\]

\[
RoleContext(RA_1,Company_A)
\]

\[
ValidTime(RA_1)=[t_1,t_2)
\]

## 2.2 关系与事件分离

“控制”是可持续关系；“投票”是一次事件。

\[
Controls(A,B,[t_1,t_2))
\]

\[
VoteEvent(V_1)
\]

\[
Voter(V_1,Zhang)
\]

\[
VoteOn(V_1,Agenda_1)
\]

\[
Choice(V_1,Agree)
\]

## 2.3 事实与证据分离

\[
Supports(Evidence,Fact)
\]

证据不是事实。年报第58页是证据，“董事会有9名成员”是事实命题。

## 2.4 法律文本与规则分离

\[
FormalizedFrom(Rule,ArticleVersion)
\]

法条是来源，规则是可执行形式化表达。任何规则必须有来源。

## 2.5 开放世界原则

\[
NotKnown(P)\neq Known(\neg P)
\]

没有发现董事会资料，不能推出公司没有董事会，只能推出：

\[
Truth(BoardExists(company))=UNKNOWN
\]

# 3. 类型系统

顶层类型：

```text
Type
├──Entity
├──Role
├──RelationInstance
├──Event
├──Fact
├──Evidence
├──Norm
├──LegalStatus
└──ProofObject
```

## 3.1 Entity

```text
Entity
├──LegalPerson
│  ├──Company
│  │  ├──LimitedLiabilityCompany
│  │  ├──CompanyLimitedByShares
│  │  └──ListedCompany
│  └──OtherOrganization
├──NaturalPerson
└──GovernanceOrgan
   ├──ShareholdersMeeting
   ├──Board
   ├──AuditCommittee
   └──ManagementBody
```

包含关系：

\[
ListedCompany\subseteq CompanyLimitedByShares
\]

\[
CompanyLimitedByShares\subseteq Company
\]

\[
Company\subseteq LegalPerson
\]

互斥关系：

\[
NaturalPerson\cap LegalPerson=\varnothing
\]

\[
GovernanceOrgan\cap NaturalPerson=\varnothing
\]

## 3.2 Role

```text
Role
├──ShareholderRole
│  ├──ControllingShareholderRole
│  └──MinorityShareholderRole
├──DirectorRole
│  ├──IndependentDirectorRole
│  ├──ChairpersonRole
│  └──ExecutiveDirectorRole
├──OfficerRole
├──ControllerRole
└──SecretaryRole
```

\[
IndependentDirectorRole\subseteq DirectorRole
\]

\[
ChairpersonRole\subseteq DirectorRole
\]

同一自然人可以同时承担多个角色，但是否合法由具体规则判断，不能由类型系统预先假定。

## 3.3 RelationInstance

带时间、证据、强度、来源或上下文的关系必须实体化。

```text
RelationInstance
├──RoleAssignment
├──Membership
├──ControlRelation
├──OwnershipRelation
├──AuthorizationRelation
└──DutyAssignment
```

例如：

\[
ControlRelation(CR_1)
\]

\[
Controller(CR_1,A)
\]

\[
Controlled(CR_1,B)
\]

\[
ControlType(CR_1,VotingControl)
\]

\[
ValidTime(CR_1)=[t_1,t_2)
\]

## 3.4 Event

事件是发生于某一时点或时间区间内、可能引起事实状态变化的对象。

```text
Event
├──AppointmentEvent
├──ResignationEvent
├──MeetingEvent
│  ├──ShareholdersMeetingEvent
│  └──BoardMeetingEvent
├──NoticeEvent
├──VoteEvent
├──ResolutionEvent
├──TransactionEvent
├──DisclosureEvent
└──EnforcementEvent
```

不变量：

\[
Event(e)\Rightarrow\exists t:OccurredAt(e,t)
\]

## 3.5 Fact

事实定义为：

\[
Fact=(Proposition,ValidTime,TruthValue,EvidenceSet)
\]

例如：

\[
BoardMemberCount(Board_A,9)
\]

它不是静态字段，而是可被证据支持、可随时间变化的命题。

# 4. 关系签名

所有关系必须定义：

\[
r:Domain\times Range\rightarrow TruthValue
\]

带时间的关系：

\[
r:Domain\times Range\times TimeInterval\rightarrow TruthValue
\]

## 4.1 INSTANCE_OF

\[
INSTANCE\_OF:Object\times Type\rightarrow TruthValue
\]

## 4.2 SUBCLASS_OF

\[
SUBCLASS\_OF:Type\times Type\rightarrow TruthValue
\]

传递性：

\[
SUBCLASS\_OF(A,B)\land SUBCLASS\_OF(B,C)
\Rightarrow SUBCLASS\_OF(A,C)
\]

## 4.3 ORGAN_OF

\[
ORGAN\_OF:GovernanceOrgan\times Company\times TimeInterval\rightarrow TruthValue
\]

同一时间点，一个具体治理机构只能属于一家具体公司：

\[
GovernanceOrgan(g)\Rightarrow\exists!c:ORGAN\_OF(g,c,t)
\]

## 4.4 Membership

不允许直接写：

\[
MemberOf(Person,Board)
\]

必须写成关系实例：

\[
Membership(m)
\]

\[
Member(m,p)
\]

\[
Organization(m,o)
\]

\[
RoleAssignmentOf(m,ra)
\]

\[
ValidTime(m)=[t_1,t_2)
\]

## 4.5 角色关系

\[
HOLDER:RoleAssignment\times Entity\rightarrow TruthValue
\]

\[
ROLE\_TYPE:RoleAssignment\times Role\rightarrow TruthValue
\]

\[
ROLE\_CONTEXT:RoleAssignment\times Entity\rightarrow TruthValue
\]

唯一性：

\[
RoleAssignment(ra)\Rightarrow\exists!x:HOLDER(ra,x)
\]

\[
RoleAssignment(ra)\Rightarrow\exists!r:ROLE\_TYPE(ra,r)
\]

## 4.6 权利、职权和义务

\[
HAS\_RIGHT:Entity\times Right\times Context\times TimeInterval\rightarrow TruthValue
\]

\[
HAS\_POWER:Entity\times Power\times Scope\times TimeInterval\rightarrow TruthValue
\]

\[
HAS\_DUTY:Entity\times Duty\times Beneficiary\times Context\times TimeInterval\rightarrow TruthValue
\]

权力必须有来源：

\[
HAS\_POWER(x,p,s,t)\Rightarrow\exists n:AUTHORIZES(n,x,p,s,t)
\]

## 4.7 事件参与关系

\[
ACTOR:Event\times Entity\rightarrow TruthValue
\]

\[
OBJECT:Event\times Entity\rightarrow TruthValue
\]

\[
PARTICIPANT:Event\times Entity\times ParticipationRole\rightarrow TruthValue
\]

ParticipationRole 至少包括：

```text
CONVENOR
CHAIR
ATTENDEE
VOTER
SELLER
BUYER
DISCLOSER
```

## 4.8 来源与证明关系

\[
FORMALIZED\_FROM:Norm\times ArticleVersion\rightarrow TruthValue
\]

\[
SUPPORTED\_BY:Fact\times Evidence\rightarrow TruthValue
\]

\[
DERIVED\_FROM:Conclusion\times ProofStep\rightarrow TruthValue
\]

# 5. 不变量

## 5.1 类型不变量

\[
IndependentDirectorRole(x)\Rightarrow DirectorRole(x)
\]

\[
Board(x)\Rightarrow GovernanceOrgan(x)
\]

\[
ListedCompany(x)\Rightarrow Company(x)
\]

## 5.2 结构不变量

\[
Board(b)\Rightarrow\exists!c:ORGAN\_OF(b,c,t)
\]

\[
Membership(m)\Rightarrow\exists ra,p,b
\]

使得：

\[
RoleAssignmentOf(m,ra)\land Holder(ra,p)\land Organization(m,b)
\]

## 5.3 规范来源不变量

\[
Norm(n)\Rightarrow\exists a:FORMALIZED\_FROM(n,a)
\]

## 5.4 结论来源不变量

\[
LegalConclusion(c)\Rightarrow\exists p:Proves(p,c)
\]

## 5.5 时间适用不变量

\[
Apply(n,f,t)\Rightarrow t\in ValidTime(n)
\]

## 5.6 未知不等于否定

\[
Truth(P)=UNKNOWN\not\Rightarrow Truth(\neg P)=TRUE
\]

# 6. 五值真值系统

\[
TruthValue=\{TRUE,FALSE,UNKNOWN,CONFLICT,NOT\_APPLICABLE\}
\]

| 值 | 唯一含义 |
|---|---|
| TRUE | 有充分事实与证据支持命题成立 |
| FALSE | 有充分事实与证据支持命题不成立 |
| UNKNOWN | 缺少足够事实或证据 |
| CONFLICT | 存在尚未消解的相互冲突事实或证据 |
| NOT_APPLICABLE | 命题或规则不适用于当前主体、行为或时间 |

AND 的核心规则：

```text
TRUE AND TRUE = TRUE
FALSE AND 任意 = FALSE
UNKNOWN AND TRUE = UNKNOWN
CONFLICT AND 非FALSE = CONFLICT
NOT_APPLICABLE AND 任意 = NOT_APPLICABLE
```

OR 的核心规则：

```text
TRUE OR 任意 = TRUE
FALSE OR FALSE = FALSE
FALSE OR UNKNOWN = UNKNOWN
CONFLICT OR 非TRUE = CONFLICT
NOT_APPLICABLE OR 任意 = NOT_APPLICABLE
```

# 7. 时间模型

## 7.1 有效时间

\[
ValidTime(x)=[t_{start},t_{end})
\]

采用左闭右开区间。

## 7.2 系统记录时间

\[
TransactionTime(x)=[s_{start},s_{end})
\]

用于记录系统何时知道该数据。

## 7.3 时间重叠

\[
Overlap([a,b),[c,d))\iff a<d\land c<b
\]

## 7.4 规则适用

\[
ApplicableAt(rule,event)
\iff OccurredAt(event,t)\land t\in ValidTime(rule)
\]

# 8. 事件语义

事件规约：

\[
EventSpec=(Input,Precondition,Transition,Postcondition,Output)
\]

## 8.1 BoardMeetingEvent

### 输入

```text
board
company
convenor
chair
notice_time
meeting_time
participants
agenda_items
votes
evidence
```

### 前置条件

\[
Board(board)
\]

\[
ORGAN\_OF(board,company,t)
\]

\[
OccurredAt(meeting,t)
\]

### 状态机

```text
PLANNED
→ NOTICED
→ CONVENED
→ VOTING
→ COMPLETED
```

异常状态：

```text
CANCELLED
FAILED_TO_CONVENE
PROCEDURALLY_DEFECTIVE
```

### 状态转换

\[
Transition:State\times Event\rightarrow State'
\]

例如：

\[
Status(m)=PLANNED\land NoticeIssued(m)
\Rightarrow Status'(m)=NOTICED
\]

### 后置条件

\[
Status(m)=COMPLETED\Rightarrow\exists r:ResolutionResult(r,m)
\]

## 8.2 VoteEvent

\[
VoteEvent(v)
\]

必须满足：

\[
\exists!p:Voter(v,p)
\]

\[
\exists!a:VoteOn(v,a)
\]

\[
\exists!c:Choice(v,c)
\]

其中：

\[
Choice\in\{Agree,Oppose,Abstain,Recused\}
\]

## 8.3 AppointmentEvent

前置条件：

\[
Candidate(p)\land TargetRole(r)
\]

后置结果：

\[
\exists ra:Holder(ra,p)\land RoleType(ra,r)\land ValidTime(ra)=[t,\infty)
\]

# 9. 法律模态语义

## 9.1 义务

\[
O(x,a,c,t)
\]

表示主体 \(x\) 在条件 \(c\) 与时间 \(t\) 下负有实施行为 \(a\) 的义务。

违反条件：

\[
O(x,a,c,t)
\land Truth(c)=TRUE
\land Truth(Performed(x,a,t))=FALSE
\land Truth(Exception(x,a,t))\neq TRUE
\Rightarrow Violation(x,a,t)
\]

## 9.2 禁止

\[
F(x,a,c,t)
\]

\[
F(x,a,c,t)
\land Truth(c)=TRUE
\land Truth(Performed(x,a,t))=TRUE
\Rightarrow Violation(x,a,t)
\]

## 9.3 允许

\[
P(x,a,c,t)
\]

允许只表示该行为不因本规则本身构成违反：

\[
P(a)\not\Rightarrow O(a)
\]

## 9.4 授权

\[
Power(x,a,effect,scope,t)
\]

授权意味着行为能够产生指定法律效果。

\[
Power(a)\Rightarrow P(a)
\]

但：

\[
P(a)\not\Rightarrow Power(a)
\]

## 9.5 权利

\[
Right(holder,claim,against,scope,t)
\]

表示权利人可向相对方主张特定请求。

# 10. 规则结构

严格规则：

\[
r=(ID,Variables,Scope,Trigger,Modality,Target,Requirement,Exception,Consequence,Priority,ValidTime,Source)
\]

示例：

\[
ListedCompany(c)
\land HasBoard(c,b)
\land 3\times IndependentCount(b)<DirectorCount(b)
\land \neg Exception(r,c,t)
\Rightarrow NonCompliant(c)
\]

同时必须满足：

\[
ApplicableAt(r,t)
\]

# 11. 规则冲突与优先级

定义：

\[
Priority(r)=(Authority,Specificity,ExceptionLevel,TemporalOrder)
\]

采用词典序比较。

## 11.1 位阶优先

\[
Authority(r_1)>Authority(r_2)\Rightarrow r_1\succ r_2
\]

## 11.2 特别规则优先

若：

\[
Scope(r_1)\subset Scope(r_2)
\]

且两规则处理同一事项，则：

\[
r_1\succ r_2
\]

## 11.3 例外优先

\[
ExceptionRule\succ GeneralRule
\]

## 11.4 时间优先

仅在同位阶、同事项、无过渡条款时：

\[
EffectiveFrom(r_1)>EffectiveFrom(r_2)
\Rightarrow r_1\succ r_2
\]

## 11.5 无法消解

若两个规则同位阶、同具体性、同时间且结论冲突：

\[
Conflict(r_1,r_2)\Rightarrow Result=CONFLICT
\]

必须转人工法律解释。

# 12. 证据语义

\[
EvidenceQuality(e)\in[0,1]
\]

\[
Supports(e,f,w)
\]

其中 \(w\) 为支持强度。

系统必须分别保存：

```text
TruthValue
Confidence
EvidenceStatus
```

置信度不能替代法律真值。

若：

\[
Supports(e_1,f,high)
\]

且：

\[
Supports(e_2,\neg f,high)
\]

则：

\[
Truth(f)=CONFLICT
\]

除非存在明确证据优先规则。

# 13. 证明结构

证明定义为有向无环图：

\[
ProofGraph=(V_P,E_P)
\]

节点：

```text
FactNode
RuleNode
InferenceNode
ConclusionNode
EvidenceNode
SourceNode
```

推理步骤：

\[
ProofStep=(Premises,Rule,Substitution,Computation,Conclusion)
\]

示例：

\[
BoardCount(B)=9
\]

\[
IndependentCount(B)=2
\]

规则：

\[
3I\geq N
\]

变量替换：

\[
I\mapsto2,\quad N\mapsto9
\]

计算：

\[
3\times2\geq9=FALSE
\]

结论：

\[
NonCompliant(B)
\]

证明完整性：

\[
Conclusion(c)\Rightarrow\exists p:Proves(p,c)
\]

# 17. 最终业务执行模型

\[
Reality
\xrightarrow{Extraction}
Claims
\xrightarrow{EvidenceAssessment}
Facts
\xrightarrow{Typing}
TypedState
\xrightarrow{EventProcessing}
State'
\xrightarrow{RuleApplication}
LegalStatus
\xrightarrow{ProofGeneration}
Conclusion
\]

整个业务逻辑不是：

```text
定义类 → 实例化 → 调用方法
```

而是：

```text
定义类型
→ 实例化实体与关系
→ 记录事件
→ 生成事实状态
→ 执行结构约束
→ 匹配法律规范
→ 处理例外与冲突
→ 计算法律状态
→ 生成证明链
```

总公式：

\[
\boxed{
LegalResult=
Prove(
Resolve(
Apply(
ApplicableRules_t,
TypedFacts_t
)
)
)
}
\]

这份规约是对象库、规则库、事件模型、数据库模式、图谱模式与推理引擎共同遵守的最高语义约束。
