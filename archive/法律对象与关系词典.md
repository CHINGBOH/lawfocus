# 法律对象与关系词典

> 项目：经济法知识图谱与上市公司治理合规推理系统  
> 文档性质：领域本体（Ontology）与关系模式（Relation Schema）初稿  
> 版本：v0.1  
> 目标：为 PostgreSQL、图数据库、规则引擎、法律 DSL、证据链和合规推理提供统一语义基础。

---

# 1. 文档目的

法律知识系统不能直接把自然语言中的所有名词都当成节点，也不能让模型自由创造关系。

本词典用于统一规定：

1. 法律世界中允许存在什么对象；
2. 每类对象的语义边界是什么；
3. 对象之间允许建立什么关系；
4. 每种关系的定义域、值域和时间属性是什么；
5. 哪些关系属于客观事实，哪些属于法律规范，哪些属于推理结果；
6. 如何把现实中的上市公司治理结构压缩成稳定、可组合、可计算的符号结构。

整个系统采用以下基本形式：

\[
\mathcal{L}=(O,R,A,T,N,E,P)
\]

其中：

| 符号 | 含义 |
|---|---|
| \(O\) | Object，对象集合 |
| \(R\) | Relation，关系集合 |
| \(A\) | Attribute，属性集合 |
| \(T\) | Time，时间结构 |
| \(N\) | Norm，法律规范集合 |
| \(E\) | Evidence，证据集合 |
| \(P\) | Proof，推理与证明结构 |

# 2. 设计原则

## 2.1 对象、角色、事件必须分离

错误表示：

```text
张三 = 董事
```

正确表示：

```text
张三
  └──通过“任职事件”──▶ 在甲公司承担董事角色
```

即：

\[
Person(张三)
\]

\[
HasRole(张三,Director,甲公司,[2025-01-01,2027-12-31])
\]

自然人是持续存在的对象，董事是法律角色，任职是带时间和证据的事件。

---

## 2.2 条文、概念、规则必须分离

法律条文是文本载体；法律概念是稳定语义；法律规则是可执行规范。

```text
公司法某条
    ↓ 定义/表达
忠实义务
    ↓ 形式化
董事不得利用职权谋取不正当利益
    ↓ 执行
具体公司治理合规判断
```

三者分别表示为：

```text
Article
Concept
Rule
```

不得把“公司法第×条”直接当成“忠实义务”本身。

---

## 2.3 事实、证据、结论必须分离

例如：

```text
证据：2025年年度报告第68页
        ↓ SUPPORTS
事实：甲公司董事会共有9名董事
        ↓ USED_BY
规则：董事会组成规则
        ↓ DERIVES
结论：董事会人数符合要求
```

表示为：

\[
Supports(Evidence,Fact)
\]

\[
Derives(Rule,Fact,Conclusion)
\]

---

## 2.4 所有法律对象和关系原则上必须可追溯

任何法律概念、规则或结论都应满足：

\[
Conclusion
\rightarrow
Rule
\rightarrow
Article
\rightarrow
LegalDocumentVersion
\rightarrow
OfficialSource
\]

---

## 2.5 所有动态关系必须带时间

法律关系不是永久静态关系。

例如：

```text
张三担任甲公司董事
```

必须记录：

```yaml
valid_from: 2025-01-01
valid_to: 2027-12-31
```

其形式为：

\[
Relation(x,y,[t_1,t_2))
\]

# 3. 顶层对象分类

所有法律对象统一继承：

```text
LegalObject
```

顶层分类如下：

```text
LegalObject
├── LegalSourceObject       法律渊源对象
├── LegalTextObject         法律文本对象
├── LegalConceptObject      法律概念对象
├── LegalSubjectObject      法律主体对象
├── GovernanceObject        公司治理对象
├── RoleObject              法律角色对象
├── NormativeObject         权利、权力、义务、责任
├── ActionEventObject       行为与事件对象
├── FactObject              事实对象
├── EvidenceObject          证据对象
├── RuleObject              法律规则对象
├── LegalStatusObject       法律状态对象
└── InferenceObject         推理与证明对象
```

# 4. 法律渊源对象词典

## 4.1 LegalSourceObject：法律渊源对象

### 定义

产生、发布、保存或证明法律规范来源的对象。

### 子类

| 对象代码 | 中文名 | 定义 |
|---|---|---|
| `Jurisdiction` | 法域 | 法律适用的国家、地区或监管辖区 |
| `Authority` | 制定或发布机关 | 制定、发布、解释、监管法律规范的机构 |
| `OfficialSource` | 官方来源 | 官方网站、公报、数据库或正式发布渠道 |
| `LegalDocument` | 法律文件 | 一部法律、法规、规章、规则或公司自治文件 |
| `LegalDocumentVersion` | 法律文件版本 | 某法律文件在特定时间范围内有效的版本 |

### 示例

```text
中华人民共和国
全国人民代表大会常务委员会
中华人民共和国公司法
中华人民共和国公司法（2023年修订版本）
```

### 核心属性

```yaml
id:
name:
source_type:
issuer:
promulgated_at:
effective_from:
effective_to:
status:
official_url:
content_hash:
```

# 5. 法律文本对象词典

## 5.1 LegalTextObject：法律文本对象

### 子类

| 对象代码 | 中文名 | 定义 |
|---|---|---|
| `Book` | 编 | 法典中的编 |
| `Part` | 分编 | 法律文本的分编 |
| `Chapter` | 章 | 法律文件章节 |
| `Section` | 节 | 章节下的细分 |
| `Article` | 条 | 法律规则的主要文本载体 |
| `Paragraph` | 款 | 条文下的自然段层级 |
| `Item` | 项 | 条款内列举事项 |
| `Sentence` | 句 | 可被进一步形式化的最小文本单元 |
| `Appendix` | 附件 | 法律文件附件、表格、目录等 |

### 结构关系

```text
LegalDocumentVersion
    └── CONTAINS ──▶ Chapter
                         └── CONTAINS ──▶ Article
                                              └── CONTAINS ──▶ Paragraph
                                                                   └── CONTAINS ──▶ Item
```

### 不变量

\[
Article(a)
\Rightarrow
\exists v:PartOf(a,v)
\]

任何条文必须属于某个具体法律版本。

# 6. 法律概念对象词典

## 6.1 LegalConceptObject：法律概念对象

### 定义

由法律文本定义、使用、解释或推导出的稳定语义单元。

法律概念不等同于条号，也不等同于某一版本的文字表达。

### 一级分类

| 对象代码 | 中文名 | 示例 |
|---|---|---|
| `EntityConcept` | 主体概念 | 公司、股东、董事、实际控制人 |
| `InstitutionConcept` | 制度概念 | 股东会、董事会、审计委员会 |
| `RoleConcept` | 角色概念 | 独立董事、董事长、董事会秘书 |
| `RightConcept` | 权利概念 | 表决权、知情权、提案权 |
| `PowerConcept` | 职权概念 | 聘任经理、审议重大交易 |
| `DutyConcept` | 义务概念 | 忠实义务、勤勉义务、披露义务 |
| `LiabilityConcept` | 责任概念 | 赔偿责任、连带责任 |
| `ActionConcept` | 行为概念 | 表决、披露、交易、任免 |
| `StateConcept` | 状态概念 | 有效、无效、合规、违规 |
| `ThresholdConcept` | 阈值概念 | 持股比例、表决权比例、人数比例 |
| `ProcedureConcept` | 程序概念 | 通知、召集、审议、表决、披露 |
| `RiskConcept` | 风险概念 | 利益冲突、关联交易、控制风险 |

### 核心属性

```yaml
concept_id:
canonical_name:
aliases:
definition:
concept_type:
upper_concept:
lower_concepts:
status:
```

### 示例

```yaml
concept_id: CONCEPT-INDEPENDENT-DIRECTOR
canonical_name: 独立董事
aliases:
  - 独董
concept_type: RoleConcept
upper_concept: 董事
```

# 12. 事实对象词典

## 12.1 FactObject：事实对象

### 定义

经证据支持、可进入规则引擎的结构化命题。

### 类型

| 对象代码 | 中文名 | 示例 |
|---|---|---|
| `EntityFact` | 主体事实 | 甲公司是上市公司 |
| `RoleFact` | 角色事实 | 张三是甲公司董事 |
| `StructureFact` | 结构事实 | 甲公司设有董事会 |
| `CountFact` | 数量事实 | 董事会有9名成员 |
| `RatioFact` | 比例事实 | 独立董事占比为1/3 |
| `ControlFact` | 控制事实 | 乙集团控制甲公司 |
| `EventFact` | 事件事实 | 甲公司实施了关联交易 |
| `ProcedureFact` | 程序事实 | 某董事已回避表决 |
| `NegativeFact` | 否定事实 | 未发现审计委员会 |
| `UncertainFact` | 不确定事实 | 是否存在关联关系尚待核实 |

### 事实状态

```text
ASSERTED      已主张
VERIFIED      已核验
DISPUTED      有争议
INFERRED      推理生成
UNKNOWN       未知
REVOKED       已撤销
```

### 重要约束

“未发现”不能自动等于“不存在”。

```text
NOT_FOUND ≠ FALSE
```

因此：

\[
Unknown(x)\neq False(x)
\]

# 14. 法律规则对象词典

## 14.1 RuleObject：规则对象

### 统一结构

\[
Rule=(S,C,M,A,X,Y,P,T,Source)
\]

其中：

| 符号 | 含义 |
|---|---|
| \(S\) | Subject，适用主体 |
| \(C\) | Condition，适用条件 |
| \(M\) | Modality，规范模态 |
| \(A\) | Action/State，要求行为或状态 |
| \(X\) | Exception，例外 |
| \(Y\) | Consequence，法律后果 |
| \(P\) | Priority，规则优先级 |
| \(T\) | Valid Time，有效时间 |
| `Source` | 法律来源 |

### 规则类型

| 对象代码 | 中文名 |
|---|---|
| `DefinitionRule` | 定义规则 |
| `ClassificationRule` | 分类规则 |
| `ObligationRule` | 义务规则 |

# 28. 关系使用层级

为了防止图谱混乱，关系分为五层。

| 层级 | 关系性质 | 示例 |
|---|---|---|
| L1 | 类型关系 | INSTANCE_OF、SUBCLASS_OF |
| L2 | 事实关系 | HAS_ROLE、CONTROLS、HAS_ORGAN |
| L3 | 法律规范关系 | REQUIRES、PROHIBITS、PERMITS |
| L4 | 证据关系 | SUPPORTS、EXTRACTED_FROM |
| L5 | 推理关系 | USES_RULE、DERIVES、DERIVED_FROM |

不得把不同层级的关系混用。

例如：

错误：

```text
公司法 ─HAS_DUTY→ 忠实义务
```

正确：

```text
公司法某条 ─EXPRESSES→ 忠实义务规则
忠实义务规则 ─IMPOSES_DUTY→ 董事
董事 ─HAS_DUTY→ 忠实义务
```

# 35. 关系校验规则

系统插入关系前必须执行类型校验。

例如：

```text
HAS_ORGAN
Domain: Company
Range: GovernanceOrgan
```

合法：

```text
甲公司 ─HAS_ORGAN→ 董事会
```

非法：

```text
张三 ─HAS_ORGAN→ 忠实义务
```

校验函数：

\[
ValidRelation(s,r,o)
=
Type(s)\in Domain(r)
\land
Type(o)\in Range(r)
\]
