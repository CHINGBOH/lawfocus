# 产品主链纠偏与实施指南

> 本文取代 `09-当前完成度评估与剩余工作指南.md` 中的执行优先级。以 `经济法知识仓库_UI功能设计文档.md` 和 `MVP产品需求与验收标准.md` 的用户任务为准；`GOAL.md` 的骨架完成不等于产品完成。

## 1. 结论

当前系统的工程骨架可运行，但不是原定的“溯源式法律超文本阅读器”。现在的界面更接近法律与合规数据演示后台：能够读取单条、执行部分规则，却不能让用户按法律目录、版本、章节、概念和来源完成阅读与理解。

| 维度 | 完成度 | 判断 |
|---|---:|---|
| 后端模型、权限、审计、五值引擎 | 85% | 核心领域能力和测试已具备 |
| 法律阅读器核心体验 | 25% | 只有三栏外壳和单条读取；缺目录、版本切换、导航、来源和对比 |
| 概念溯源与小综合 | 20% | 只有简化演示浮层；真实公司法没有可读的溯源概念链 |
| 治理与事实证据工作区 | 45% | 可查询/录入，但仍是数据表与 JSON 表单 |
| 合规检查与证明 | 65% | 可运行；缺预检、整改和完整结构化穿透 |
| 正式法源与规则 | 35% | 有真实数据和单规则切片；其余规则仍待审核 |
| **按原产品定义的完成度** | **约 45%** | 可演示工程能力，不能交付预定用户体验 |

## 2. 先解决什么

先完成下面的用户主链，再扩张真实法源、Docker、CI 和性能工作：

```text
搜索/打开法律
→ 版本、章节和条文定位
→ 阅读原文与来源
→ 概念定义及出处
→ 小综合
→ 公司事实与证据
→ 合规结论
→ 规则、事实、证据、法条证明
```

当前法律列表把所有版本固定跳到第 108 条，阅读页左栏也不是目录。这是最高优先级的产品缺陷。

## 3. 正确的执行切片

| 切片 | 用户可见结果 | 必要后端/契约 | 退出条件 |
|---|---|---|---|
| U0 法律阅读器 | 任意打开公司法第 1–266 条，按版本、章节和条号浏览 | 版本条文目录、章节树、相邻条文、来源元数据 | 能读第 1、108、266 条；切版本；上一/下一条可用 |
| U1 概念与小综合 | 概念显示定义、出处、版本、语境；右栏只显示有来源的综合 | 概念详情、来源关系、`text_segments[]` | 无审核来源时显示“资料不足”，不能生成概念链接 |
| U2 首页与检索 | 按法律名、条号、概念、公司进入任务 | 统一搜索与分组结果 | 返回版本和命中位置 |
| U3 治理与证据 | 治理全景、事实卡、证据页码/原句、确认与争议状态 | 事实/证据状态与来源定位 | 默认界面不暴露 JSON 作为业务录入方式 |
| U4 合规与证明 | 预检缺失事实、逐项结论、整改提示、完整穿透 | 适用预检、缺失规格、证明引用 | 五种结果各有明确下一步 |
| U5 真实规则 | 已审核规则集真正绑定直接法源 | 参数化阈值、双审、版本化规则 | 一条规则完整跑通后再逐条扩展 |
| U6 发布验收 | 真实操作可自动回归 | Playwright、Docker、CI、性能与故障脚本 | 不用 `TestClient` 或人工走查冒充浏览器 E2E |

## 4. U0：下一位 Agent 的首个任务

范围只限“真实公司法阅读器”；不要同时改规则、Agent、Docker 或性能。

- [ ] 法律列表入口改为“打开目录”或默认第 1 条，删除固定 `articleNo: '108'`。
- [ ] 增加版本条文目录接口，返回 `article_no`、`chapter_no`、`section_no`、条文摘要和相邻条号。
- [ ] 左栏实现法律名、版本选择、生效状态、章节分组、条文列表和当前定位。
- [ ] 中栏实现条号、正文、公布/施行时间、官方来源、上一条/下一条。
- [ ] 右栏继续使用“小综合”；真实公司法缺少已审核输入时，明确显示“暂无经审核的综合内容”，不能填充演示概念。
- [ ] 为第 1、108、266 条和版本切换补 API、组件测试及 OpenAPI 更新。

建议新增而非破坏现有精确条文接口：

```text
GET /api/v1/laws/{law_code}/versions/{version_name}/articles
GET /api/v1/laws/{law_code}/versions/{version_name}/articles/{article_no}/navigation
```

前者服务章节树；后者返回当前条文、相邻条号、版本元数据和官方来源。

## 5. U1–U4 的边界

### U1 概念与小综合

- 概念链接只能消费后端 `text_segments[]`，不能用字符串匹配生成。
- 浮层至少展示定义、来源条文、有效期、当前语境和审核状态。
- “深入查看”进入概念详情；返回后保留条文、版本和阅读上下文。

### U3 治理与证据

- 公司入口按董事会、委员会、控制、披露、证据、检查组织，不平铺数据库表。
- 事实卡使用业务字段和可读状态；JSON 仅放高级详情。
- 证据展示标题、来源、页码、原句、发布日期、支持关系和审核状态；能跳原文时才显示链接。

### U4 合规与证明

- 提交前列出适用规则、评价时点和缺失事实，并提供补录跳转。
- 证明默认是逐步文字；JSON 放高级展开区。
- 每步可进入规则、事实、证据和条文；无权限或目标缺失时给出原因。

## 6. 延后但仍必须完成的事项

真实法源、规则参数化、双审、Playwright、Docker、CI、性能、备份恢复和数据治理都是发布门槛，但应排在 U0–U4 的可用产品主链之后。

真实公司法和贵州茅台数据继续标记为 `UNVERIFIED`，直至人工审核。已有真实来源规则切片不代表十条规则已经完成，也不构成对外法律意见。

## 7. 工作规则

- 每个切片同时提交接口契约、后端、前端、自动化测试和运行证据。
- 不以“页面存在”“API 返回”或“固定演示条文可显示”作为完成条件。
- UI 文档中的用户任务优先于 `GOAL.md` 的目录与骨架描述；冲突时先记录产品决策。
- 需求与数据模型不匹配时先修契约和模型，不在 Vue 页面硬编码补丁。
