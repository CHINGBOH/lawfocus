# 法律规则数据结构设计规范

> 项目：经济法知识图谱与上市公司治理合规推理系统  
> 文档定位：规则层核心数据规范  
> 目标：把自然语言法律条文转换为可存储、可版本化、可执行、可解释、可追溯的形式规则

---

# 1. 文档目标

法律文本本身不是可执行规则。

例如：

> 上市公司董事会成员中应当至少包括一定比例的独立董事。

机器不能直接稳定执行这句话，因为它还缺少：

- 适用主体是谁；
- 适用前提是什么；
- “应当”是什么法律模态；
- 被约束对象是谁；
- 比例如何计算；
- 是否存在例外；
- 规则何时生效；
- 与其他规则冲突时谁优先；
- 违反后产生什么法律状态；
- 该规则来源于哪一部规范、哪一个版本、哪一条；
- 本次判断使用了哪些公司事实和证据。

因此，需要将自然语言规范编译为结构化法律规则。

本文定义：

\[
Rule =
(
Identity,
Scope,
Condition,
Modality,
Requirement,
Exception,
Consequence,
Priority,
Time,
Source,
Execution,
Proof
)
\]

即：

```text
规则身份

+

适用范围

+

触发条件

+

法律模态

+

规范要求

+

例外

+

法律后果

+

优先级

+

有效时间

+

法律来源

+

执行信息

+

证明信息
```

# 3. 规则对象的总体结构

建议每条规则采用如下统一结构：

```yaml
rule:
  identity: {}
  classification: {}
  scope: {}
  trigger: {}
  modality: {}
  requirement: {}
  exception: {}
  consequence: {}
  priority: {}
  temporal: {}
  source: {}
  evidence_policy: {}
  execution: {}
  explanation: {}
  audit: {}
```

对应数学结构：

\[
r =
(
I,
K,
S,
C,
M,
Q,
X,
Y,
P,
T,
L,
E,
Exec,
Explain,
Audit
)
\]

| 符号 | 名称 | 含义 |
|---|---|---|
| \(I\) | Identity | 规则唯一身份 |
| \(K\) | Classification | 规则分类 |
| \(S\) | Scope | 适用范围 |
| \(C\) | Condition | 触发条件 |
| \(M\) | Modality | 必须、禁止、允许等 |
| \(Q\) | Requirement | 规范要求或约束 |
| \(X\) | Exception | 例外与排除条件 |
| \(Y\) | Consequence | 合规状态、责任、整改要求 |
| \(P\) | Priority | 法律位阶及冲突优先级 |
| \(T\) | Temporal | 生效、失效及适用时间 |
| \(L\) | Legal Source | 法律来源 |
| \(E\) | Evidence Policy | 事实认定与证据要求 |
| \(Exec\) | Execution | 执行方式 |
| \(Explain\) | Explanation | 人类可读解释 |
| \(Audit\) | Audit | 创建、审核和版本记录 |

# 4. 规则身份 Identity

## 4.1 字段定义

```yaml
identity:
  rule_id: CN-LISTED-GOV-BOARD-IND-0001
  rule_code: BOARD.IND.RATIO.MIN
  canonical_name: 独立董事最低比例规则
  short_name: 独董比例规则
  version: 1.0.0
  status: active
```

## 4.2 字段说明

| 字段 | 类型 | 是否必填 | 含义 |
|---|---|---:|---|
| `rule_id` | UUID/String | 是 | 全局唯一且永久不变 |
| `rule_code` | String | 是 | 人类可读的稳定编码 |
| `canonical_name` | String | 是 | 规则规范名称 |
| `short_name` | String | 否 | 界面展示简称 |
| `version` | SemVer | 是 | 形式规则自身版本 |
| `status` | Enum | 是 | draft、review、active、deprecated、retired |

## 4.3 编码建议

```text
司法辖区
-
领域
-
模块
-
规则主题
-
序号
```

例如：

```text
CN-LISTED-GOV-BOARD-0001

CN-COMPANY-SHAREHOLDER-0008

CN-SEC-DISCLOSURE-0015
```

规则 ID 与法条号不能绑定。

错误：

```text
COMPANY-LAW-ARTICLE-180-RULE
```

因为法律修订后条号可能变化。

正确：

```text
CN-COMPANY-DIRECTOR-LOYALTY-0001
```

然后用来源关系连接不同法律版本。

# 5. 规则分类 Classification

```yaml
classification:
  domain: company_law
  subdomain: listed_company_governance
  module: board_governance
  rule_type: structural_constraint
  legal_function: obligation
  reasoning_type: deterministic
```

## 5.1 领域分类

```text
company_law

securities_law

listing_governance

information_disclosure

related_party_transaction

shareholder_governance

board_governance

director_duties

internal_control
```

## 5.2 规则类型

建议第一版使用：

| 类型 | 含义 | 示例 |
|---|---|---|
| `classification_rule` | 对象分类 | 满足条件则属于控股股东 |
| `structural_constraint` | 组织结构约束 | 上市公司须设置董事会 |
| `quantitative_constraint` | 数值约束 | 独立董事比例要求 |
| `qualification_rule` | 任职资格 | 不得担任董事的情形 |
| `authority_rule` | 权限规则 | 某事项由股东会审议 |
| `procedure_rule` | 程序规则 | 会议召集和表决程序 |
| `prohibition_rule` | 禁止规则 | 董事不得侵占公司财产 |
| `permission_rule` | 允许规则 | 公司可以设置某机构 |
| `disclosure_rule` | 披露义务 | 重大事项必须披露 |
| `liability_rule` | 责任规则 | 造成损失应承担赔偿责任 |
| `exception_rule` | 例外规则 | 特定情形不适用一般规则 |
| `definition_rule` | 法律定义 | 符合条件属于关联方 |
| `priority_rule` | 规则冲突规则 | 特别规定优先 |
| `evidentiary_rule` | 证据认定规则 | 某事实须由特定材料证明 |

# 6. 适用范围 Scope

规则不能只写“适用于上市公司”。

需要形式化定义适用对象、地域、市场、组织、行为和时间。

```yaml
scope:
  jurisdiction: CN
  regulated_subject:
    type: ListedCompany
  market:
    in:
      - SSE
      - SZSE
      - BSE
  organization:
    type: Board
  action_types: []
  excluded_subject_types: []
```

## 6.1 主体类型约束

```yaml
regulated_subject:
  type: ListedCompany
  predicates:
    - field: listing_status
      operator: eq
      value: listed
```

数学：

\[
ListedCompany(x)
\land
ListingStatus(x)=Listed
\]

## 6.2 适用范围不是触发条件

二者要区分：

```text
Scope

规则理论上对哪些对象有效
```

```text
Trigger

某次事实是否触发该规则
```

例如：

```text
适用范围：

上市公司
```

```text
触发条件：

公司已设董事会，并存在董事成员数据
```

# 7. 条件结构 Condition Tree

条件是规则引擎最核心的数据。

不建议把复杂条件只保存为字符串：

```json
{
  "condition": "listed == true and board_size > 0"
}
```

因为：

- 不易校验；
- 不易版本比较；
- 不易可视化；
- 不易转换为 SQL、Datalog 或 SMT；
- 不易做变量绑定。

建议使用抽象语法树：

\[
ConditionTree
\]

---

## 7.1 原子条件

一个原子条件：

```yaml
field: company.company_type
operator: eq
value: listed_company
```

形式：

\[
company.company\_type
=
listed\_company
\]

---

## 7.2 逻辑组合

```yaml
trigger:
  all:
    - field: company.company_type
      operator: eq
      value: listed_company

    - field: board.exists
      operator: eq
      value: true
```

数学：

\[
ListedCompany(x)
\land
HasBoard(x)
\]

---

## 7.3 OR 条件

```yaml
trigger:
  any:
    - field: company.market
      operator: eq
      value: SSE

    - field: company.market
      operator: eq
      value: SZSE
```

数学：

\[
ListedOnSSE(x)
\lor
ListedOnSZSE(x)
\]

---

## 7.4 NOT 条件

```yaml
trigger:
  not:
    field: company.status
    operator: eq
    value: delisted
```

数学：

\[
\neg Delisted(x)
\]

---

## 7.5 嵌套条件

```yaml
trigger:
  all:
    - field: company.company_type
      operator: eq
      value: listed_company

    - any:
        - field: transaction.type
          operator: eq
          value: asset_purchase

        - field: transaction.type
          operator: eq
          value: asset_sale
```

数学：

\[
ListedCompany(x)
\land
(
AssetPurchase(e)
\lor
AssetSale(e)
)
\]

# 9. 法律模态 Modality

法律规则不能只保存“要求”。

需要区分：

\[
O(A)
\]

必须：

```text
OBLIGATION
```

\[
F(A)
\]

禁止：

```text
PROHIBITION
```

\[
P(A)
\]

允许：

```text
PERMISSION
```

建议：

```yaml
modality:
  type: OBLIGATION
  strength: mandatory
  source_expression: 应当
```

## 9.1 模态类型

| 值 | 含义 |
|---|---|
| `OBLIGATION` | 必须实施 |
| `PROHIBITION` | 不得实施 |
| `PERMISSION` | 可以实施 |
| `ENTITLEMENT` | 享有权利 |
| `AUTHORIZATION` | 获得职权 |
| `RECOMMENDATION` | 倡导或建议 |
| `PRESUMPTION` | 推定成立 |
| `DEEMED` | 法律拟制 |
| `EXEMPTION` | 免除义务 |
| `DISCRETION` | 有权裁量 |

## 9.2 强度

```text
mandatory

strong

default

soft

guidance
```

法律强制规则与治理建议不能混为一类。

# 10. 规范要求 Requirement

Requirement 描述规则要求的目标状态。

```yaml
requirement:
  target:
    type: Board
    selector:
      relation: HAS_ORGAN
      from: regulated_subject

  constraint:
    expression:
      operator: gte
      left:
        field: board.independent_director_count
      right:
        expression:
          operator: multiply
          operands:
            - field: board.director_count
            - value: 0.333333
```

数学：

\[
IndependentCount(b)
\geq
\frac{1}{3}
BoardCount(b)
\]

---

## 10.1 状态要求

```yaml
requirement:
  state:
    field: board.exists
    operator: eq
    value: true
```

---

## 10.2 数值要求

```yaml
requirement:
  constraint:
    left:
      field: board.member_count
    operator: gte
    right:
      value: 5
```

---

## 10.3 比例要求

不要直接使用浮点数：

```text
0.333333333
```

建议保存有理数：

```yaml
right:
  rational:
    numerator: 1
    denominator: 3
```

执行：

\[
3I \geq N
\]

避免浮点误差。

---

## 10.4 关系要求

```yaml
requirement:
  relation:
    source:
      variable: director
    relation_type: HAS_DUTY
    target:
      concept: LoyaltyDuty
```

---

## 10.5 事件要求

```yaml
requirement:
  event:
    type: BoardResolution
    must_exist: true
    before:
      event_variable: transaction
```

表示：

\[
BoardResolution(e_1)
\land
Time(e_1)<Time(transaction)
\]

---

# 11. 变量与绑定

规则不能写死某家公司。

使用变量：

```yaml
variables:
  company:
    type: ListedCompany

  board:
    type: Board

  director:
    type: Director
```

关系约束：

```yaml
bindings:
  - relation: HAS_ORGAN
    source: company
    target: board

  - relation: HAS_MEMBER
    source: board
    target: director
```

执行时：

```text
company = 甲上市公司

board = 甲公司第六届董事会

director = 张三
```

这叫：

\[
Substitution
\]

变量替换：

\[
\theta
=
\{
company\mapsto A,
board\mapsto B,
director\mapsto Zhang
\}
\]

# 12. 例外结构 Exception

例外不能作为备注文本。

必须可执行。

```yaml
exception:
  any:
    - exception_id: EX-001
      condition:
        field: company.special_governance_mode
        operator: eq
        value: true

    - exception_id: EX-002
      condition:
        field: rule_exemption.approved
        operator: eq
        value: true
```

数学：

\[
GeneralCondition
\land
\neg Exception
\rightarrow
Requirement
\]

即：

\[
C
\land
\neg X
\Rightarrow
Q
\]

---

## 12.1 例外效果

```yaml
exception_effect:
  type: waive_requirement
```

可能值：

| 值 | 含义 |
|---|---|
| `waive_requirement` | 免除义务 |
| `replace_requirement` | 替换为另一要求 |
| `reduce_threshold` | 降低阈值 |
| `extend_deadline` | 延长期限 |
| `change_consequence` | 改变法律后果 |
| `route_to_manual_review` | 转人工判断 |

# 13. 法律后果 Consequence

规则不满足后，不一定直接产生“违法”。

需要区分：

```text
事实缺失

规则不适用

未满足约束

治理风险

程序瑕疵

法律违规

责任成立
```

建议：

```yaml
consequence:
  on_satisfied:
    legal_status: COMPLIANT

  on_violated:
    legal_status: NON_COMPLIANT
    severity: major
    issue_code: BOARD_INDEPENDENCE_RATIO_DEFECT

  on_unknown:
    legal_status: UNKNOWN
    required_facts:
      - board.director_count
      - board.independent_director_count
```

---

## 13.1 五值判断

\[
Result
\in
\{
PASS,
FAIL,
WARNING,
UNKNOWN,
NOT\_APPLICABLE
\}
\]

| 状态 | 含义 |
|---|---|
| `PASS` | 满足规则 |
| `FAIL` | 不满足强制规则 |
| `WARNING` | 存在风险或软约束偏离 |
| `UNKNOWN` | 缺少事实或证据 |
| `NOT_APPLICABLE` | 规则不适用 |

---

## 13.2 严重程度

```text
info

minor

moderate

major

critical
```

严重程度不等于法律位阶。

# 14. 规则优先级 Priority

规则冲突不能依赖代码顺序。

优先级必须显式建模。

```yaml
priority:
  authority_rank: 100
  specificity_rank: 80
  temporal_rank: 20240701
  exception_rank: 0
  manual_override: null
```

总体比较：

\[
Priority(r)
=
(
Authority,
Specificity,
Temporal,
Exception
)
\]

建议采用词典序比较。

---

## 14.1 位阶示例

仅作为系统内部排序模型，具体司法适用须由法律专家确认。

```text
法律

>

行政法规

>

部门规章

>

规范性文件

>

交易所自律规则

>

公司章程

>

内部制度
```

数据：

```yaml
authority:
  source_type: law
  rank: 100
```

---

## 14.2 特别规则优先

```yaml
specificity:
  subject_depth: 4
  condition_count: 5
  explicit_special_rule: true
```

例如：

\[
ListedCompany
\subseteq
Company
\]

上市公司专门规则通常比一般公司规则更具体。

---

## 14.3 新旧规则

```yaml
temporal_precedence:
  effective_from: 2024-07-01
```

但不能简单地认为新规则总优先。

还要检查：

- 是否同一位阶；
- 是否同一事项；
- 是否明确废止；
- 是否存在过渡条款；
- 是否适用事件发生时间。

# 15. 时态结构 Temporal

规则必须至少记录：

```yaml
temporal:
  promulgated_at: 2023-12-29
  effective_from: 2024-07-01
  effective_to: null
  repealed_at: null
  transition_period: null
```

## 15.1 有效时间

\[
ValidTime(r)
=
[t_{start},t_{end})
\]

适用：

\[
t_{event}
\in
ValidTime(r)
\]

---

## 15.2 系统记录时间

建议增加双时态：

```yaml
transaction_time:
  recorded_from: 2026-07-15T20:00:00+08:00
  recorded_to: null
```

区分：

```text
法律现实中什么时候有效

系统什么时候知道并记录
```

---

## 15.3 追溯适用

```yaml
retroactivity:
  enabled: false
  mode: none
```

可能值：

```text
none

full

limited

procedural_only
```

# 16. 法律来源 Source

规则必须能穿透到原始规范。

```yaml
source:
  document_id: DOC-COMPANY-LAW
  version_id: VER-2023-REVISION
  article_id: ARTICLE-180
  paragraph: 1
  item: null
  source_text: "……"
  official_source_id: SRC-NPC-2023
```

## 16.1 一条规则可以有多个来源

```yaml
sources:
  - relation: primary_basis
    article_id: ARTICLE-001

  - relation: supplementary_basis
    article_id: ARTICLE-002

  - relation: definition_basis
    article_id: ARTICLE-003
```

关系类型：

```text
PRIMARY_BASIS

SUPPLEMENTARY_BASIS

DEFINITION_BASIS

EXCEPTION_BASIS

PROCEDURAL_BASIS

LIABILITY_BASIS
```

# 17. 证据策略 Evidence Policy

# 21. 完整 YAML 示例

以下为示意结构，不代表具体法律结论。

```yaml
rule:
  identity:
    rule_id: CN-LISTED-GOV-BOARD-IND-0001
    rule_code: BOARD.IND.RATIO.MIN
    canonical_name: 独立董事最低比例约束
    version: 1.0.0
    status: active

  classification:
    domain: company_law
    subdomain: listed_company_governance
    module: board_governance
    rule_type: quantitative_constraint
    legal_function: obligation
    reasoning_type: deterministic

  variables:
    company:
      type: ListedCompany

    board:
      type: Board

  bindings:
    - relation: HAS_ORGAN
      source: company
      target: board

  scope:
    jurisdiction: CN

    regulated_subject:
      variable: company

  trigger:
    all:
      - field: company.listing_status
        operator: eq
        value: listed

      - field: board.exists
        operator: eq
        value: true

  modality:
    type: OBLIGATION
    strength: mandatory
    source_expression: 应当

  requirement:
    constraint:
      operator: gte

      left:
        field: board.independent_director_count

      right:
        expression:
          operator: multiply

          operands:
            - field: board.director_count

            - rational:
                numerator: 1
                denominator: 3

  exception:
    none: true

  consequence:
    on_satisfied:
      result: PASS
      legal_status: COMPLIANT

    on_violated:
      result: FAIL
      legal_status: NON_COMPLIANT
      severity: major
      issue_code: BOARD_INDEPENDENCE_RATIO_DEFECT

    on_unknown:
      result: UNKNOWN
      required_facts:
        - board.director_count
        - board.independent_director_count

  priority:
    authority_rank: 80
    specificity_rank: 90

  temporal:
    effective_from: 2024-07-01
    effective_to: null

  source:
    document_id: DOC-EXAMPLE
    version_id: VER-EXAMPLE
    article_id: ARTICLE-EXAMPLE

  evidence_policy:
    required_fact_types:
      - BoardMemberCountFact
      - IndependentDirectorCountFact

    accepted_source_types:
      - annual_report
      - official_announcement

    confidence_threshold: 0.8

  execution:
    engine: constraint_solver
    evaluation_mode: forward
    deterministic: true
    incremental: true

  explanation:
    fail_template: >
      董事会共有{{board.director_count}}名董事，
      其中独立董事{{board.independent_director_count}}名，
      未满足规则要求。

  audit:
    created_by: legal_engineer_001
    reviewed_by:
      - legal_expert_001
```

```text
技术修复
```

建议：

```text
PATCH

不改变法律含义的技术修复

MINOR

法律含义或执行结果变化
```

# 36. 最终抽象

法律规则不是一句文本。

它是一个带类型、时间、来源、例外和后果的状态变换函数。

\[
\boxed{
Rule:
State
\times
Facts
\times
Time
\rightarrow
LegalState
}
\]

完整表示：

\[
\boxed{
r=
(
S,
C,
M,
Q,
X,
Y,
P,
T,
L,
E
)
}
\]

其中：

```text
S

适用主体
```

```text
C

触发条件
```

```text
M

法律模态
```

```text
Q

规范要求
```

```text
X

例外
```

```text
Y

法律后果
```

```text
P

规则优先级
```

```text
T

有效时间
```

```text
L

法律来源
```

```text
E

证据要求
```

执行：

\[
Facts
+
ApplicableRule
+
Evidence
\rightarrow
Evaluation
\rightarrow
Proof
\]

最终系统中的规则层可以理解为：

\[
\boxed{
法律规则DSL
+
规则版本库
+
规则编译器
+
规则执行引擎
+
证明生成器
}
\]

法律文本是源代码。

规则 DSL 是中间语言。

Datalog、SQL、Python 和 SMT 是目标执行语言。

规则执行结果是法律状态。

证明链是完整的执行轨迹。
