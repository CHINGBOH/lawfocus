# 经济法知识仓库 UI 功能设计文档

> 项目定位：经济法历史版本仓库、法律概念溯源系统、上市公司治理合规推理平台  
> 核心交互：以法律条文为入口，以已溯源概念为超链接，以右侧“小综合文字”为解释主体。

## 1. 产品目标

本系统不是普通法规检索网站，也不是单纯知识图谱展示工具。它应帮助用户完成：

1. 阅读指定法律版本和具体条文；
2. 理解条文中的核心法律概念；
3. 点击核心名词，穿透到法定定义、法律出处和概念层级；
4. 阅读由多个已溯源概念组合形成的条文“小综合”；
5. 查看条文在制度中的位置及共同适用规则；
6. 比较历史版本；
7. 将条文转换为可执行规则；
8. 将上市公司事实与规则匹配；
9. 输出合规、风险、不合规、未知或不适用结论；
10. 从结论反向穿透到事实、证据、规则和原始法条。

核心链路：

```text
问题 → 条文 → 概念 → 定义来源 → 规则 → 事实 → 结论 → 证明
```

## 2. 设计原则

### 2.1 以阅读为主，图谱为辅

知识图谱主要服务后台关联、路径检索和解释生成。前端默认以连续法律文本、小综合解释、概念超链接和法条出处为主。

### 2.2 右侧只显示“小综合文字”

右侧不默认堆叠大型概念卡片或关系图，而是一段连续、可读、已完成溯源的综合解释。

示例：

> 本条中的[公司]属于[营利法人]的一种，具有独立的权利义务归属和责任财产；[股东]通过出资或持股取得成员资格，但与公司并非同一法律主体；[董事]是自然人在特定任期内承担的治理角色，其履职行为可能归属于公司，也可能因违反[忠实义务]或[勤勉义务]而产生个人责任。因此，判断本条责任归属时，应先区分法人责任、股东责任和董事个人责任。

其中方括号名词均为可点击的法律概念超链接。

### 2.3 概念链接必须完成法律溯源

每个正式概念链接至少绑定：

```text
concept_id
法定定义来源
适用语境
有效版本
上位概念
下位概念
易混淆概念
当前条文中的语义作用
```

### 2.4 未知不等于否定

必须区分：

```text
不存在
未发现
尚未核实
存在冲突
不适用
```

### 2.5 所有内容带时间和版本

条文、概念、规则、事实、角色关系和结论均需展示适用版本、生效时间、失效时间、评价时间或事实有效期间。

### 2.6 所有结论可反向穿透

任何结论都能回答：

```text
为什么？
用了哪些事实？
事实来自什么证据？
用了哪条规则？
规则来自哪个法条版本？
是否存在例外或冲突？
```

## 3. 用户角色

- 法律研究人员：阅读法律、比较版本、研究概念源流；
- 律师与企业法务：查找规则、识别责任主体、分析合规；
- 董秘与治理人员：检查治理结构、补充事实证据、查看整改；
- 法律知识工程师：维护概念、关系、规则和测试；
- 审核人员：审核来源、规则、事实、证据和证明链。

## 6. 法律条文阅读器

### 6.1 三栏布局

```text
┌──────────────┬──────────────────────────┬──────────────────────┐
│ 法律目录      │ 条文正文                  │ 溯源式小综合          │
│ 法律版本      │ 当前条文                  │ 综合解释文字          │
│ 章节目录      │ 上一条 / 下一条           │ 核心名词超链接        │
│ 条文定位      │ 历史版本标记              │ 出处与穿透入口        │
└──────────────┴──────────────────────────┴──────────────────────┘
```

建议宽度：左 20%，中 50%，右 30%。

### 6.2 左栏

包含法律名称、当前版本、版本切换、生效状态、章节目录、条文目录和全文搜索。

### 6.3 中栏

展示条号、正文、款项层级、公布与施行时间、官方来源、历史对应条文。核心名词以轻量链接样式显示。

### 6.4 右栏：小综合生成顺序

```text
本条直接规范什么
→ 核心主体是谁
→ 核心概念在法律类型系统中的位置
→ 主体之间如何区分
→ 权利、义务、权限或责任如何分配
→ 还需结合哪些程序、例外或责任规则
→ 现实判断时需要关注什么
```

## 7. 法律概念超链接

### 7.1 交互

- 单击：显示轻量浮层；
- 点击“深入查看”：右栏切换为完整概念解释；
- Ctrl / Command + 单击：新标签页打开概念详情；
- 返回：保留浏览路径。

概念路径示例：

```text
法人 → 营利法人 → 公司 → 股份有限公司 → 上市公司
```

### 7.2 轻量浮层

示例：

```text
法人

法定定义：
具有民事权利能力和民事行为能力，
依法独立享有民事权利、承担民事义务的组织。

出处：
《民法典》第57条

当前语境：
用于确定独立权利义务及责任归属主体。

上位概念：
民事主体

下位概念：
营利法人、非营利法人、特别法人

[查看原文] [深入查看]
```

### 7.3 数据结构

```yaml
concept_link:
  concept_id: CONCEPT-LEGAL-PERSON
  display_text: 法人
  context_id: COMPANY_LAW_CONTEXT
  definition_source_id: ARTICLE-CIVIL-CODE-57
  definition_version_id: VERSION-CURRENT
  relation_to_current_article: SUBJECT_DEFINITION
```

## 9. 小综合生成规则

### 9.1 可用数据

```text
当前条文语义槽位
条文核心概念
概念法定定义
概念上下位关系
责任能力
条文规则结构
共同适用规则
例外规则
责任承接规则
```

### 9.2 禁止数据

```text
纯向量相似结果
未经审核的大模型推断
无出处的学理总结
未确认的概念关系
无版本信息的法条
```

### 9.3 生成模板

```text
本条以【主体】为规范对象，
在【适用情境】下，
通过【法律模态】规范【行为或状态】。

其中，【核心概念A】在法律上属于【上位概念】，
其主要法律作用是【作用】；
【核心概念B】与其区别在于【区别】。

本条还需结合【程序规则】、
【例外规则】和【责任规则】共同适用。

现实判断时，应重点核实【事实要素】。
```

### 9.4 LLM 边界

LLM只负责语句衔接、表达简化和篇幅控制，不得自行增加法律命题、创造概念关系、改变优先级或补充无来源结论。

## 10. 三种阅读深度

- 快速模式：80—120 字；
- 专业模式：300—500 字；
- 形式模式：类型、变量、谓词、条件树、模态、例外、来源和形式表达式。

三种模式必须来自同一结构化数据。

## 11. 历史版本

提供时间轴、上一版本对比、现行版本对比和指定版本对比。

差异维度：

```text

主体变化
义务变化
程序变化
例外变化
责任变化
规则变化
```

概念历史包括首次出现、定义变更、外延变化和相关条文迁移。

## 13. 合规检查

流程：

```text
选择公司
→ 选择评价时间
→ 选择治理模块
→ 确认适用规则
→ 核对事实与证据
→ 运行检查
→ 查看结论与证明
```

结果统一为：

```text
符合
不符合
存在风险
资料不足
不适用
```

单项结果展示自然语言结论、输入事实、计算过程、适用规则、法律出处、证据、例外和证明链。

## 18. 核心接口

### 条文接口

```text
GET /laws/{law_id}/versions/{version_id}/articles/{article_id}
```

### 小综合接口

```text
GET /articles/{article_version_id}/synthesis
```

返回分段结构，而不是单一字符串：

```yaml
synthesis:
  text_segments:
    - text: 本条中的
    - concept_id: CONCEPT-COMPANY
      text: 公司
    - text: 属于
    - concept_id: CONCEPT-FOR-PROFIT-LEGAL-PERSON
      text: 营利法人
```

### 概念浮层接口

```text
GET /concepts/{concept_id}/preview
```

### 概念详情接口

```text
GET /concepts/{concept_id}
```

## 19. 审核机制

概念链接进入正式小综合前必须满足：

```text
唯一ID
定义来源已确认
版本已确认
语境已确认
关系已审核
出处可直接定位
```

待审核内容必须标注“待审核”，且不得作为自动合规结论的唯一依据。

## 20. 响应式设计

## 22. 最终产品定义

本系统的核心前端是：

> 以法律条文为入口，以已溯源法律概念为超链接，以小综合文字为主要解释形式，以规则、事实、证据和证明为底层支撑的法律超文本阅读与推理界面。

可命名为：

- **溯源式法律超文本阅读器**
- **法律概念血缘阅读器**

其核心体验类似万维网，但每个超链接背后都是经过法律溯源、版本确认和关系审核的结构化知识节点。
