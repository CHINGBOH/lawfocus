# 用户权限与内容审核模型

> 采用 RBAC 加资源范围约束。前端隐藏按钮不构成授权，所有权限由后端按当前身份、组织和资源状态重新验证。

## 1. 角色

| 角色 | 主要权限 | 禁止事项 |
|---|---|---|
| `Reader` | 阅读已发布法源、概念、规则和证明 | 查看组织私有事实、修改内容 |
| `ComplianceUser` | 管理本组织事实与证据、执行检查 | 发布知识或修改他组织数据 |
| `KnowledgeEditor` | 创建法源、概念、关系和规则草稿 | 审批自己的草稿、直接发布 |
| `LegalReviewer` | 审核法源效力、概念语义和规则法律正确性 | 替代技术测试或绕过双审 |
| `TechnicalReviewer` | 审核 Schema、执行、性能和测试 | 判断法源法律效力 |
| `Publisher` | 发布双审通过且测试通过的版本 | 编辑待发布内容、跳过门禁 |
| `Auditor` | 只读查看版本、操作和证明审计 | 修改业务数据 |
| `SystemAdmin` | 账号、组织、角色和系统配置 | 默认读取证据正文或作法律审核 |

## 2. 资源范围

- 公共知识：已发布法源、概念、关系和规则，对授权用户只读。
- 组织数据：公司事实、证据、检查与结论，以 `tenant_id` 隔离。
- 草稿空间：编辑者可修改自己的草稿；提交审核后锁定内容，只能撤回或新建修订。
- 审计数据：追加写入，业务接口不得更新或删除。

## 3. 状态机

```text
DRAFT → IN_REVIEW → LEGAL_APPROVED → TECH_APPROVED → PUBLISHED → DEPRECATED
  ↑          │              │              │
  └──────────┴── CHANGES_REQUESTED ────────┘
```

法源和概念可省略技术审核，但规则必须法律、技术双审。提交者不得担任同一版本的最终法律审核者；`Publisher` 只执行发布门禁，不改变审核结论。

## 4. 高风险操作门禁

| 操作 | 后端前置条件 |
|---|---|
| 发布规则 | 双审通过、批准测试集全绿、来源有效、无未处置冲突 |
| 修改已发布内容 | 创建新版本，不允许原位修改 |
| 删除事实或证据 | 默认软删除；有引用时禁止物理删除 |
| 导出证据 | 组织权限、用途记录、字段脱敏和审计事件 |
| Agent 写入草稿 | 明确工具权限、Schema 校验；只能写 `DRAFT` |

Agent 无任何审核、发布、删除或授权能力；“用户已确认”必须来自可信 UI 确认事件和后端会话，不能来自模型文本。

## 5. 审计事件

每次登录失败、权限拒绝、创建、提交、审核、发布、废止、导出和规则执行记录：

```text
event_id, trace_id, actor_id, tenant_id, action, resource_type,
resource_id, resource_version, decision, reason_code, occurred_at
```

敏感内容只记录哈希、标识符和脱敏摘要，不把证据全文、令牌或模型隐藏提示写入日志。

## 6. 验收

- [ ] 跨组织读写均被后端拒绝并留审计记录。
- [ ] 编辑者不能审批自己的规则版本。
- [ ] 测试失败、来源失效或审核缺失时无法发布。
- [ ] 已发布内容只能通过新版本变更。
- [ ] Agent 即使构造合法参数也无法越权发布。
