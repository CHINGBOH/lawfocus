## 3. R1：规则参数化

### 3.1 要解决的问题

`apps/api/app/services/rule_handlers.py` 仍存在人数 `2`、人数 `3`、比例 `1/3`、过半数等业务参数。处理器可以包含比较算法，但不得包含具体法律阈值；阈值必须来自实际执行的 `LegalRuleVersion.requirement_expression`。

### 3.2 推荐结构

统一最小表达：

```json
{
  "operator": "gte",
  "value": 2,
  "unit": "person"
}
```

比例规则：

```json
{
  "operator": "gte_ratio",
  "numerator": 1,
  "denominator": 3
}
```

严格过半：

```json
{
  "operator": "gt_ratio",
  "numerator": 1,
  "denominator": 2
}
```

### 3.3 实现步骤

1. 新增不可变 `RuleExecutionContext`，至少包含 `rule_version_id`、`rule_code`、`requirement_expression`、`evaluation_time`。
2. `RuleEngine` 从固定 `RuleSetMember` 解析具体 `LegalRuleVersion`，把上下文传给处理器。
3. 建立确定性参数解析器，对运算符、整数、分母、单位和额外字段做严格校验。
4. 人数比较读取 `value`；比例使用整数交叉相乘，禁止转浮点。
5. 参数缺失或非法时拒绝执行并返回稳定错误，不回退到代码默认阈值。
6. 种子脚本为十条演示规则写入完整表达。
7. 证明步骤记录采用的表达、左右计算值和规则版本。

### 3.4 测试要求

- 同一个处理器绑定不同规则版本参数时必须产生不同结果。
- `1/3`、`2/5`、严格大于 `1/2` 等比例边界使用参数化测试。
- 分母为零、负人数、未知运算符、字符串数字和额外字段必须被拒绝。
- 检查历史继续引用执行当时的规则版本；发布新版本不能改变旧结论。
- 搜索业务阈值，确认处理器内不再出现固定 `threshold = 2/3` 或固定比例乘数。

### 3.5 退出条件

- [ ] 十条规则参数均来自规则版本。
- [ ] 处理器只保留通用算法和领域数据读取。

- [ ] 全量后端测试、Ruff、Mypy 通过。

## 5. R3：Playwright 浏览器 E2E

### 5.1 工程接入

在 `apps/web` 增加 Playwright 依赖、`playwright.config.ts` 和 `tests/e2e/`。配置 `webServer` 或专用脚本启动真实 API 与 Vite；E2E 使用独立 `lawfocus_e2e` 数据库，不得复用开发库。

建议命令：

```bash
pnpm exec playwright install --with-deps chromium
pnpm e2e
pnpm e2e:ui
```

根 `make e2e` 应同时运行后端 API 验收和前端 Playwright 测试。

### 5.2 数据策略

- 每次 E2E 前重建测试 schema、迁移并播种固定演示数据。
- 使用稳定业务 code 或页面文本定位对象，测试代码不写数据库 UUID。
- 不并行修改同一规则状态；需要修改时为测试创建独立规则。
- 密码通过环境变量注入，trace、视频和截图仅在失败时保留。

### 5.3 必须覆盖的流程

#### E2E-01 阅读与溯源

Reader 登录，打开法律版本和条文，点击概念，验证定义、审核状态和法源定位。

#### E2E-02 事实与证据

ComplianceUser 选择公司，创建事实、创建证据元数据并关联；刷新页面后数据仍存在且有效期间正确。

#### E2E-03 合规检查

选择主体、评价时点和已发布规则集，确认并提交；断言请求使用 `Idempotency-Key`，结果页至少验证 `TRUE`、`FALSE`、`UNKNOWN`、`CONFLICT`。`NOT_APPLICABLE` 可用专门演示主体或 API+UI 混合准备数据，但最终状态必须由页面渲染。

#### E2E-04 证明穿透

从冲突或违反结论进入证明，依次打开规则、事实、证据和条文来源，再返回检查页。

#### E2E-05 双审门禁

编辑者提交规则；法律审核者审核；技术审核者审核；发布者尝试发布。分别验证成功发布和缺少测试导致发布失败两条路径。

#### E2E-06 权限与租户

Reader 不能查看租户事实，编辑者不能自审，非 Publisher 不能发布，另一个租户不能读取检查结果。页面必须显示可理解的拒绝状态，后端必须返回 401/403。

#### E2E-07 Agent 降级

禁用 Agent 后打开综合内容，页面仍正常；没有已审核内容时显示资料不足，不生成新法律命题。

### 5.4 稳定性规则

- 优先使用 `getByRole`、label 和稳定 `data-testid`，不依赖 CSS 层级。
- 等待明确的网络响应或页面状态，不使用固定 `sleep`。
- 测试失败保存截图、trace 和后端日志；成功运行不保留大文件。
- 同一测试连续运行三次均通过后，才能标记 F6 完成。

## 8. R6：性能、故障和恢复

### 8.1 正式性能基准

按 `04-MVP性能基准与容量验收方案.md` 生成固定种子大数据集。使用 Locust、k6 或等价工具实现以下场景：条文读取、检索、概念详情、十条规则检查、证明链读取和事实写入。

报告至少包含：数据规模、环境、提交 SHA、并发、吞吐、P50/P95/P99、错误率、CPU、内存和慢查询。烟雾测试不得冒充正式性能结果。

### 8.2 故障测试

- 数据库短暂不可用：请求返回稳定错误，恢复后连接池可用。
- 重复合规请求：同一幂等键不生成重复检查。
- Agent 超时/不可用：自动进入确定性降级，不影响规则执行。
- 非法规则参数：拒绝执行并审计，不采用默认值。
- 并发发布：只有合法状态转换成功，不产生两个相互冲突的发布结果。

### 8.3 备份恢复

在非生产测试库完成一次 `pg_dump` 和恢复演练。恢复后核对法律版本、规则集成员、事实证据关系、检查结果和审计事件数量；敏感材料只使用合成数据。

退出条件：正式性能目标达到，或形成明确的未达标清单、瓶颈证据和后续容量计划；故障与恢复测试可重复执行。
