# MVP 产品需求与验收标准

> 本文定义第一版可交付产品的需求基线和完成标准。若与形式化语义发生冲突，以《法律形式化元模型与精确语义规约》为准。

## 1. 产品目标

面向公司法务、律师、合规人员和法律知识工程师，建设一个以法律条文阅读为入口、以结构化规则为判断依据、以证据和证明链为解释基础的上市公司治理合规工具。

MVP 必须跑通以下闭环：

```text
查找条文 → 阅读条文 → 查看概念及来源 → 录入治理事实与证据
→ 执行规则 → 查看五值结论 → 反向检查规则、事实、证据和法源
```

系统提供辅助分析，不替代执业律师、法务负责人或其他有权人员作出最终法律判断。

## 2. 用户与核心任务

| 用户 | 核心任务 | MVP 结果 |
|---|---|---|
| 法务、律师、合规人员 | 定位现行条文并理解概念 | 获得带版本、时间和来源的条文及概念说明 |
| 合规人员 | 检查公司治理结构 | 获得可解释的五值结论和缺失资料清单 |
| 法律知识工程师 | 维护概念、规则和测试 | 完成审核、测试、发布和版本追踪 |
| 审核人员 | 复核知识与结论 | 查看变更、来源和完整证明链 |

## 3. MVP 范围

### 3.1 P0 必须交付

1. **法律仓库**：收录经人工确认的《公司法》现行版本及 MVP 规则直接引用的配套规范；保留原文、条款层级、生效时间和来源。
2. **条文阅读器**：提供法律目录、条文正文、概念链接和右侧“小综合”；每段综合说明可追溯到输入数据。
3. **概念库**：覆盖公司、股东、控股股东、实际控制人、董事、独立董事、董事会和审计委员会等 MVP 对象。
4. **治理事实录入**：支持主体、组织、任职、成员、持股或控制等结构化事实，并关联证据与有效期间。
5. **规则执行**：至少发布 10 条经审核规则，覆盖组织设置、人数、比例、任职有效性、审计委员会结构和基本控制关系。
6. **结果解释**：输出 `TRUE`、`FALSE`、`UNKNOWN`、`CONFLICT`、`NOT_APPLICABLE`，并展示适用规则、命中事实、证据、来源及推导步骤。
7. **规则治理**：规则经过草稿、审核、测试、发布和废止状态；未通过测试不得发布。

### 3.2 P1 可后续交付

- 法律版本可视化对比、批量事实导入、全文检索优化和语义检索。
- 更多交易所规则、定时检查、通知、报表和团队协作。
- Z3 复杂约束、Neo4j 图数据库及通用问答 Agent。

### 3.3 明确不做

- 不自动给出“绝对合法”或诉讼结果预测。
- 不让 LLM 创造法律命题、法源、概念关系、规则优先级或事实。
- 不以向量相似度、模型置信度或缺少材料直接替代法律真值。
- 不在 MVP 中覆盖证券发行、并购重组、反垄断等完整经济法领域。

## 4. 功能需求

| 编号 | 功能 | 必要行为 |
|---|---|---|
| FR-01 | 法律版本 | 原文只增不改；条文可定位到法律版本和有效期间 |
| FR-02 | 阅读与检索 | 按法律、章节、条号打开条文；搜索结果显示命中版本 |
| FR-03 | 概念溯源 | 概念链接展示定义、上下位概念、语境和已审核来源 |
| FR-04 | 小综合 | 仅组合已审核的条文语义、概念和规则；分段返回来源关联 |
| FR-05 | 事实与证据 | 事实具有评价时间或有效期间；证据与事实分开存储 |
| FR-06 | 合规检查 | 固定评价时点执行确定性规则，缺失事实返回 `UNKNOWN` |
| FR-07 | 冲突处理 | 按既定优先级计算；无法消解时返回 `CONFLICT` |
| FR-08 | 证明链 | 每个结论可穿透至规则版本、事实、证据和条文版本 |
| FR-09 | 内容审核 | 未审核内容不可作为自动合规结论的唯一依据 |
| FR-10 | 审计 | 记录规则、概念、事实和结论的创建者、版本与时间 |

## 5. 职责与信任边界

| 层 | 负责 | 不负责 |
|---|---|---|
| 前端 | 阅读、录入、状态展示、人工确认 | 判定规则成立或伪造审核状态 |
| 后端 | 权限、版本、数据约束、规则执行、审计 | 用生成文本替代权威数据 |
| 规则引擎 | 五值计算、时间判断、冲突消解、证明步骤 | 开放式解释或补造缺失事实 |
| LLM/Agent | 检索辅助、句子组织、长度控制、候选提示 | 最终法律判断、规则发布或改写法源 |
| 人工审核者 | 法源确认、概念与规则审核、责任判断 | 将未经核实的模型输出直接发布 |

## 6. 数据与接口契约

核心对象使用稳定 ID 和显式版本。所有动态关系采用半开区间 `[valid_from, valid_to)`；系统记录时间与法律有效时间分离。

首批接口至少包括：

```text
GET  /api/v1/laws/{law_id}/articles/{article_id}
GET  /api/v1/articles/{article_id}/synthesis
GET  /api/v1/concepts/{concept_id}
POST /api/v1/facts
POST /api/v1/compliance-checks
GET  /api/v1/compliance-checks/{check_id}
GET  /api/v1/conclusions/{conclusion_id}/proof
```

每个写接口必须校验身份、权限、对象版本和业务不变量。合规检查请求应包含主体、评价时点、规则集版本和幂等键；响应应包含结论状态、缺失事实、适用或排除原因及 `proof_id`。具体字段以 OpenAPI 契约为准。

## 7. 非功能要求

| 类别 | MVP 指标 |
|---|---|
| 溯源 | 已发布规则 100% 关联有效条文版本；结论 100% 关联规则版本 |
| 正确性 | 10 条发布规则的批准测试集通过率 100% |
| 性能 | 本地基准数据下，条文读取 P95 ≤ 1 秒，单主体 10 条规则检查 P95 ≤ 3 秒（不含外部模型） |
| 安全 | 未授权用户不能发布规则或修改已审核内容；敏感审计字段不返回普通用户 |
| 可审计 | 发布、废止、事实变更和规则执行均产生带时间及操作者的记录 |
| 可用性 | 错误、空数据、资料不足、冲突和不适用均有独立 UI 状态 |

## 8. 验收场景

### AC-01 条文与概念溯源

给定一个已收录条文，用户打开阅读页并点击“独立董事”。页面必须显示定义、来源条文、版本和有效时间；返回上级条文时上下文保持不丢失。

### AC-02 规则通过

给定事实和证据均完整且满足规则的公司，在指定评价时点执行检查。系统返回 `TRUE`，并可依次查看结论、规则版本、命中事实、证据和法源。

### AC-03 规则违反

给定独立董事比例低于已发布规则阈值的事实，系统返回 `FALSE`，展示实际值、要求值、计算过程及来源，不使用模型自由推断。

### AC-04 资料不足

缺少董事人数或任职有效期时，系统返回 `UNKNOWN` 和明确的缺失事实清单，不返回 `FALSE`。

### AC-05 不适用与例外

主体不在规则适用范围时返回 `NOT_APPLICABLE`；满足已发布例外时展示例外规则和来源。

### AC-06 规则冲突

构造同等级且无法消解的冲突规则，系统返回 `CONFLICT`，保留双方规则和冲突说明，不静默选择结果。

### AC-07 发布控制

规则缺少来源、测试失败或未审核时，发布操作必须被后端拒绝并记录原因。

### AC-08 LLM 边界

当检索材料缺少已审核定义时，小综合显示“资料不足”或省略该命题；不得根据模型常识补写定义或结论。

## 9. 测试与 Eval 准入

每条规则至少包含：通过、违反、边界、缺失事实、不适用、例外和冲突测试；不适用的类别需说明原因。数据库约束、五值逻辑、时间区间和优先级采用单元及属性测试；API 采用契约与集成测试；核心闭环采用端到端测试。

LLM/Agent 另设 Eval 集，覆盖正确引用、拒绝无来源补写、提示注入、工具失败和回归案例。确定性法律判断不得使用模型评分代替自动化断言。

## 10. 里程碑与完成定义

| 阶段 | 产物 | 退出条件 |
|---|---|---|
| M0 需求冻结 | 本文、对象清单、10 条规则清单 | 范围、责任人和验收案例完成评审 |
| M1 数据基础 | 法律版本、条文、概念、事实和证据模型 | 迁移可重复执行，核心不变量测试通过 |
| M2 规则闭环 | 规则编辑、发布、执行和证明链 | AC-02 至 AC-07 全部通过 |
| M3 阅读闭环 | 条文阅读、概念溯源和小综合 | AC-01、AC-08 通过，无来源内容不展示为事实 |
| M4 MVP 验收 | 部署文档、测试报告、已知限制和回滚方案 | 所有 P0、非功能指标和安全检查通过 |

MVP 只有在 P0 功能、八个验收场景、审计记录、部署说明和已知限制清单全部具备时，才可标记完成。

## 11. 待产品负责人确认

- 首批权威法源的具体版本、获取渠道和更新责任人。
- 10 条 MVP 规则的最终清单及业务优先级。
- 用户账号、组织隔离和审核角色的实际授权模型。
- 性能基准数据规模与部署环境。
- 真实公司材料能否进入测试环境，以及脱敏、保存和删除规则。
