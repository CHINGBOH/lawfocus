# 项目文档索引与实施顺序

> 本页是项目入口。2026-07-20 起，项目定位收敛为**法律体系概念穿透学习工具**，替代此前的上市公司治理合规推理系统定位；旧文档见 `archive/`。

## 1. 项目是什么

给定一部法律（如《公司法》《合同法》……），帮助使用者把其中的每一个法律概念，沿着**整个法律体系**做穿透式溯源学习：

- 这个概念在哪部法律的哪一条被定义？
- 它的上位/下位概念是什么？
- 其他法律（甚至其他部门法）里怎么引用或使用这个概念？
- 溯源链条最终落在哪一条真实条文、哪一个版本。

这是一个**学习/理解工具**，不是企业合规判断工具：不录入公司治理事实、不执行确定性规则、不产出"合规/违规"结论。

| 2 | `02-学习工具产品需求与验收标准.md` | 用户任务、界面形态、验收标准、架构边界 |

## 3. 架构基线

```text
法律仓库（DB，结构化真相）
  LegalDocument → LegalVersion → Article/ArticleVersion
  概念图谱（DB，结构化真相）
  Concept → ConceptVersion → 关系（定义于/上位/下位/跨法引用/条文出处）
       ↓
   RAG 索引（检索层，基于法律仓库+概念图谱内容构建）
       ↓
   LLM harness（组织解释、回答追问、引导下钻）
```

- **法律仓库 + 概念图谱必须是数据库里的结构化事实**，不能由 LLM 生成或臆测——这是溯源可信的前提。
- **RAG + LLM** 负责检索、组织语言、回答用户追问，但不得凭空发明概念关系或法条内容。
- 不需要规则引擎、五值逻辑执行、规则审核发布状态机、RBAC/多租户、治理事实与证据录入、审计追踪——这些是上一版"企业合规系统"定位下的机械流程，个人学习工具不需要预先搭建这类重型骨架。

## 4. 变更规则

- 新增一部法律或扩展概念图谱范围：先在 `01` 文档补充数据模型，再导入内容。
- 修改概念图谱的关系类型或溯源规则：同步更新 `01` 文档与前端概念超链接组件。
- 修改产品范围或验收标准：记录决策人、原因、日期，更新 `02` 文档。
- 法源更新：新增版本，不覆盖旧文本（沿用原合规系统定位下即已确立的 append-only 原则）。
